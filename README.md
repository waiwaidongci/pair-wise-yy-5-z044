# 手工织锦纹样 · 可恢复排产台

在原有网格绘制、色线统计、断线风险之上，把**网格、色线、织造批次、交付包**接成一条可恢复的排产链：
双端合版冲突仲裁、批次容量排队、开织快照冻结、交付包失效重算、断网按批次号恢复。

直接打开 `index.html` 使用；核心规则在不依赖 DOM 的 `src/core.js`，可用 `npm test` 跑测试。

## 规则与实现对照

| 要求 | 实现 |
| --- | --- |
| 同格两边都改 → 保留车间值，另一版留冲突 | `mergePlan()`：车间/打样各自记 `touched`；双改且不同值时取车间值，写入 `conflicts`，合版视图红框标出 |
| 冲突未处理不生成交付包 | `resolveConflict()` 裁决（保留车间值/采用打样值）；`confirmPlan()` 与 `generatePackage()` 均拦截未处理冲突 |
| 每批锁定经向列数、纬向行数、色线容量 | `lockBatch()` 固化 `lockedDims`、`capacities`；超容量状态为 `queued`，`shortfall.perColor[]` 逐色号写明 `need/capacity/gap` |
| 超出容量排队、写明缺口 | 缺口总量与逐色缺口在批次面板、统计区展示；`recheckBatch()` 补足容量后转 `locked` 才能开织 |
| 任一格色号变化 → 用色统计、断线风险、交付包失效重算 | `editCells()` 每次改动 `revision+1` 并作废旧合版；`invalidatePackagesOnEdit()` 清未开织批次的交付包；统计与风险由 `computeUsage/computeRisk` 按当前网格重算 |
| 已开织批次保留原快照 | `startBatch()` 冻结 `snapshot`（网格、用量、风险、校验和）；开织后出的交付包为 `frozen` 冻结版，后续改格不影响 |
| 断网/写入中断按批次号恢复 | 回传队列以 `批次号+类型+序号` 为键；失败保留 `pending`，`outboxFlush()/Repository.recover()` 联网后补发，已确认不重发 |
| 重复回传只认首次 | 相同载荷判重返回 `duplicate`；同键不同载荷抛 `DUPLICATE_BATCH_NO`；内存服务端同样去重 |
| 旧方案缺批次号 → 迁成首版 | `Repository.bootstrapLegacy()` 读取旧 `zfl31Pattern`，分配首个批次号，`version=1`，生成首版快照并登记迁移回传 |

批次号在一个方案内固定（如 `B0007`），同批次号下多次投产用批次序号 `seq` 区分；
回传键为 `B0007::batch.lock#1`、`B0007::batch.lock#2`，因此"按批次号恢复"和"下一批不被误判重放"同时成立。

## 页面操作

1. **车间稿 / 打样间稿**两个视图分别拖动填色（蓝框＝车间改过、橙框＝打样改过）。
2. **合版**：双改格保留车间值并标冲突；在右侧逐条裁决后**确认新版**（版本 +1）。
3. **锁定批次**：填各色线容量（空＝不限）；超额会排队并列出每个色号缺口，补容量后"调整容量重算"。
4. **开织**即冻结快照；之后车间/打样继续改稿只影响下一批，本批交付包始终出冻结版。
5. 左侧可**断开网络 / 模拟写入中断**，回传挂起为待发；恢复联网后点"按批次号恢复同步"补发；"模拟旧稿重复回传"验证只认首次。
6. "迁入旧稿"可演示无批次号旧稿自动成为首批次号首版；"导出当前方案 JSON"包含批次、容量、缺口、快照与交付包。

## 结构与测试

- `src/core.js`：全部业务规则（浏览器/Node 通用的 UMD 模块）
- `src/fakeServer.js`：内存服务端 + 可离线/可中断通道（演示与测试）
- `src/app.js`：DOM 控制层，只调用核心层
- `test/core.test.js`：22 条规则单测（冲突、容量、快照失效、幂等恢复、迁移、端到端）
- `test/ui.smoke.test.js`：1 个 jsdom 驱动真实页面的全链路冒烟用例

npm install
npm test        # node --test，共 23 个用例
